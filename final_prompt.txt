# ** New Enhancement Scenario: Log Viewer Enhancement

## **Context**

You are a software engineer inheriting a very primitive internal tool called **`log_viewer.py`**, which implements:

```python
def search_logs(path, keyword):
    # returns a list of matching raw lines
```

It works, but the output is unstructured, hard to read, and the function is not extensible.

Your task is to **enhance the tool** by improving output clarity, adding multiple formatting modes, and modularizing the architecture.

This is an **Enhancement** task — the tool works, but it can be significantly improved.

---

# **1. Current Problems**

### **1.1 Output lacks structure**

* Shows raw text only
* No context lines, no indicators, no summaries
* Hard to interpret

### **1.2 No extensibility**

* No way to add pretty-printing, JSON mode, filters
* Logic is tightly coupled and non-modular

### **1.3 No summary information**

* User doesn’t know how many lines matched
* No structured metadata

---

# **2. Enhancement Requirements**

You must develop an enhanced log viewer with:

### **A. Structured Output**

Each result must include:

* Line number
* Highlighted keyword
* Optional context lines (configurable)

### **B. Summary Section**

At least:

* Number of matches
* Total lines scanned
* Earliest/latest timestamps (if parseable)

### **C. Multiple Output Formats**

Implement:

* Plain text structured format
* JSON mode
* Pretty console output mode (ANSI coloring allowed)

### **D. Modular Architecture**

Split code into components, for example:

```
log_viewer/
    reader.py
    searcher.py
    formatters/
        text.py
        json_fmt.py
        pretty.py
```

(Exact structure flexible, as long as responsibilities are separated.)

---

# **3. Demonstration Requirement**

Provide:

1. A sample log file
2. Output from original tool
3. Output from enhanced tool in text + JSON modes
4. Brief explanation of improvements

---

# **4. Automated Testing Requirements (Pytest-style)**

Instead of printing `"ENHANCEMENT CHECK PASSED"`, you must deliver:

### **A. A reusable test suite inside a `tests/` directory**

Example structure:

```
tests/
    test_text_output.py
    test_json_output.py
    test_summary.py
    test_semantics.py
```

Tests must check:

1. **Enhanced text output contains:**

   * Section headers
   * Line numbers
   * Highlighted keyword

2. **JSON output mode works:**

   * Produces well-formed JSON list
   * Each result includes required metadata

3. **Semantic correctness is preserved:**

   * Number of matches equals original behavior
   * All matched lines still correspond to the same text lines

4. **Architecture does not regress:**

   * Enhanced implementation uses modular structure

### **B. One-click test entry script**

Provide a **`run_tests.py`** in the project root that:

* Discovers and runs all `tests/` files
* Prints test results normally (pytest or unittest)
* Exits with correct status code

Example:

```bash
python run_tests.py
```

### **C. Reusable Environment Requirements**

* Must run using only Python standard library + pytest (pytest optional)
* No external dependencies
* Should work for future similar enhancement tasks simply by replacing:

  * `log_viewer_original.py`
  * enhanced implementation files

---

   * Architecture overview

2. **Enhanced modular implementation**

3. **Before/After example outputs**

4. **`tests/` folder with complete test files**

6. **The actual test results from running the script in your environment**
